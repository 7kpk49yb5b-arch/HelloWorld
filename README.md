## 一、知识学习栏（技能树）

按优先级分层：**P0 = 不会就挂，P1 = 问到就加分，P2 = 锦上添花**

### 🌳 模块 A：Java 核心与进阶 `P0`

- **Java SE 基础**
  - 与 C++ 对比学：无指针、自动内存管理、单继承 + 接口、值传递 vs 引用传递
  - 集合框架：`ArrayList` / `LinkedList` / `HashMap` / `ConcurrentHashMap` 源码级理解
  - 泛型、异常体系、IO/NIO
- **Java 并发编程** ⭐ *面试重灾区*
  - 线程生命周期与状态转换、`Thread`/`Runnable`/`Callable`
  - `synchronized`（锁升级：偏向锁→轻量锁→重量锁）、`volatile`（可见性 + 禁止重排）
  - `ReentrantLock`、`AQS` 原理、`CAS` + `ABA` 问题
  - 线程池：**7 大参数、工作流程、拒绝策略**（必背）
  - `ThreadLocal`（内存泄漏问题）、`CountDownLatch`/`Semaphore`/`CyclicBarrier`
  - `JMM` 内存模型、`happens-before` 规则
- **JVM** ⭐ *你的差异化优势区*
  - 内存区域：堆 / 方法区（元空间）/ 虚拟机栈 / 本地方法栈 / 程序计数器
  - 垃圾回收：可达性分析、标记-清除/复制/标记-整理、分代收集
  - 收集器：Serial / ParNew / CMS / **G1** / ZGC
  - 类加载机制：**双亲委派模型**及如何打破
  - OOM 排查：`jps` `jstat` `jmap` `jstack` + MAT 分析 dump

### 🌳 模块 B：计算机基础（八股文主战场）`P0`

- **数据结构与算法**（贯穿全程，不集中突击）
  - 必刷类型：数组 / 链表 / 栈队列 / 哈希表 / 二叉树 / 堆 / 图
  - 必刷算法：二分、双指针、滑动窗口、回溯、动态规划、贪心、DFS/BFS、排序
  - 目标量：**LeetCode Hot 100 至少刷 2 遍 + 《剑指 Offer》经典 50 题**
- **计算机网络**
  - 五层/七层模型、TCP vs UDP
  - **三次握手 / 四次挥手**（为什么不是两次/三次）、TIME_WAIT
  - TCP 可靠传输：滑动窗口、拥塞控制、流量控制、重传机制
  - HTTP：状态码、GET/POST 区别、HTTP1.1/2.0/3.0 差异
  - HTTPS：TLS 握手流程、对称 + 非对称加密、CA 证书
  - 经典题：**从输入 URL 到页面显示发生了什么**（能讲 5 分钟）
- **操作系统**
  - 进程 vs 线程 vs 协程、进程间通信方式
  - 线程同步：互斥锁、信号量、死锁四条件与预防
  - 内存管理：虚拟内存、分页分段、页面置换算法
  - **IO 多路复用**：`select` / `poll` / `epoll` 区别（LT vs ET）
  - 用户态 / 内核态、系统调用开销
- **MySQL**
  - 索引：**B+ 树**（为什么不是 B 树/哈希）、聚簇索引 vs 二级索引、回表、最左前缀、覆盖索引、索引失效场景
  - 事务：ACID、四种隔离级别、脏读/不可重复读/幻读
  - **MVCC**：undo log 版本链 + ReadView（高频考点）
  - 锁：行锁/表锁/间隙锁/next-key lock、死锁排查
  - 日志：redo log / undo log / binlog（两阶段提交）
  - SQL 优化：`EXPLAIN` 分析、慢查询定位

### 🌳 模块 C：框架与中间件 `P0/P1`

- **Spring** `P0`
  - **IoC / DI**：BeanFactory vs ApplicationContext
  - **AOP**：JDK 动态代理 vs CGLIB、切面/切点/通知
  - Bean 生命周期、循环依赖（三级缓存）、作用域
  - 事务：`@Transactional` 传播行为、失效场景
- **Spring Boot** `P0`
  - 自动配置原理（`spring.factories` / `@Conditional`）
  - 常用注解、配置文件、`Starter` 机制
  - 手写一个自定义 Starter（面试加分）
- **MyBatis** `P0`
  - ORM 映射、动态 SQL、`#{}` vs `${}`（SQL 注入）
  - 一级缓存 / 二级缓存、插件机制
- **Redis** `P1`
  - 五种基本类型 + 底层结构（SDS / 跳表 / 压缩列表）
  - 使用场景：缓存、分布式锁、计数器、排行榜
  - **缓存穿透 / 击穿 / 雪崩** 成因与解法（必考）
  - 持久化：RDB vs AOF、混合持久化
  - 过期策略与内存淘汰策略、主从复制、哨兵、Cluster
  - 一致性问题：缓存更新策略、双写一致性
- **Kafka** `P1`
  - 为什么需要 MQ：解耦 / 异步 / 削峰
  - 核心概念：Topic / Partition / Consumer Group / Offset
  - 三大保证：**不丢失、不重复消费、顺序性**
  - 高性能原因：顺序写、零拷贝、批量压缩、PageCache
- **Spring Cloud（微服务）** `P1`
  - Nacos（注册中心 + 配置中心）、OpenFeign（远程调用）
  - Gateway（网关：路由、限流、鉴权）
  - 熔断降级 Sentinel、负载均衡 LoadBalancer
  - *要求：大二不必精通源码，但必须说出"为什么要用、怎么用的"*

### 🌳 模块 D：加分项 —— Agent 开发 `P2 ⭐`

> JD 明确写了"有 agent 开发经验优先"。这是**投入产出比最高的加分项**，大多数同龄人没做。

- 了解 LLM 基础概念：Token、Prompt、Function Calling、RAG、Embedding
- 技术选型：**LangChain4j** 或 **Spring AI**（Java 生态）
- 动手项目：接入大模型 API（通义千问 / 智谱 / DeepSeek），做一个
  - 带**多轮记忆**的问答助手（ChatMemory）
  - 或 **RAG 应用**：把自己的博客/笔记向量化，做"基于个人知识库的智能问答"
  - 或 **Agent 任务编排**：能调用工具（查天气、查数据库、调接口）
- 进阶：在服务器上部署向量数据库（Milvus / Chroma）+ 本地模型（Ollama）

### 🌳 模块 F：机器学习 / 深度学习（对接服务外包大赛）`P2`

> 详细路线见配套文档《机器学习与服务外包大赛·双线合流路线图.md》，此处只列主干。

- **数学补课**（20h 够用即止）：线性代数直觉、概率统计、梯度下降 —— 别啃《统计学习方法》
- **Python 栈**：语法（有 C++ 基础 2 天速通）+ NumPy + Pandas + Matplotlib

- **LLM 应用** ⭐：Prompt、RAG、Function Calling、Agent 编排（**与模块 D 完全重合**）

### 🌳 模块 E：工程能力（服务器实验室）`P1`

- **Linux**：不用面板，纯命令行。SSH、`vim`、`chmod`、`ps`、`top`、`netstat`、`grep`、`systemctl`、定时任务 `cron`

## 三、学习方法论（比计划更重要）

### 📌 1. 三遍学习法（用于硬骨头知识点）

> 适用于：HashMap 源码、synchronized 锁升级、MVCC、GC 算法这类"看一遍看懂了，一周后全忘"的内容

1. **第一遍 · 输入**：看视频/文章，不纠结细节，**只求知道有什么**
2. **第二遍 · 输出**：合上资料，自己画流程图 / 写博客 / 讲给别人听。卡住的地方就是你的真盲区
3. **第三遍 · 复述**：3 天后、1 周后各复述一次。能流畅讲 3 分钟 = 真正掌握

### 📌 2. 八股文的正确背法

❌ **错误做法**：把面经答案复制粘贴到文档里，考前突击朗读
✅ **正确做法**：
- 每题按 **「一句话结论 → 展开解释 → 举个场景 → 追问预案」** 四段式整理
- 例：`synchronized 和 ReentrantLock 的区别？`
  - 结论：一个是 JVM 关键字自动释放，一个是 JDK 层面 AQS 实现需手动释放
  - 展开：可中断、可超时、公平性、条件队列的差异
  - 场景：高并发下需要 tryLock 超时控制时用 Lock
  - 追问预案：为什么 JDK1.6 后 synchronized 性能不差了？（锁升级）
- **每天 3-5 题，滚动复习**，用 Anki 或自制卡片

### 📌 3. 项目学习的正确姿势

- **先跑通再理解**：跟着教程做一遍 → 关闭教程自己再做一遍 → 加自己的功能
- **每个项目必须能回答这 5 个问题**（面试官 100% 会问）：
  1. 这个项目解决了什么问题？
  2. 整体架构是怎样的？为什么这么设计？
  3. 你遇到的最难的技术问题是什么？怎么解决的？
  4. 有没有性能瓶颈？怎么优化的？（QPS、响应时间数据）
  5. 如果重构，你会改哪里？为什么？
- **量化你的项目**：不要写"使用了 Redis 缓存"，要写"引入 Redis 缓存热点文章，接口 P99 从 320ms 降至 45ms"

### 📌 4. 时间分配建议

| 时间段 | 内容 | 说明 |
|---|---|---|
| 碎片时间（通勤/课间） | 刷算法题、看八股卡片 | 20-30 min/次 |
| 整块时间（晚上/周末） | 写代码、看源码、做项目 | 2-3h 不被打断 |
| 每周日晚上 | 复盘 + 下周计划 | 30 min，检查交付物 |

### 📌 5. 输出倒逼输入

- 每周至少写 **1 篇技术笔记**（掘金 / CSDN / 自建博客）
- 面试官看到你有持续输出的博客习惯，好感度直接拉满
- 面试时可以甩出域名："这是我部署在自己服务器上的项目和博客，您可以随时访问" —— **绝杀**

## 四、服务器利用路线（你的云端实验室）

> 拥有一台服务器 = 从"学生"到"后端工程师"的分水岭。**千万别只用来搭梯子或放静态网页。**

### 阶梯式玩法

| 阶段 | 内容 | 面试价值 |
|---|---|---|
| **L1 · Linux 生存**（第 1-2 周） | SSH 连接、**不用宝塔面板**、熟练 `ls/vim/ps/top/netstat/grep/systemctl`；手动装 JDK17 + Maven + Git；**安全加固**（改 SSH 端口、禁 root 密码登录、UFW 防火墙）；学会打快照 | 面试第一关必考 Linux 常识，这是练兵场 |
| **L2 · Docker 容器化**（第 3-4 周） | 装 Docker + Compose；写 Dockerfile 把 Spring Boot 项目打成镜像；`docker-compose.yml` 一键起 应用+MySQL+Redis；理解容器网络与数据卷 | 微服务基石，"我本地能跑"问题的终结者 |
| **L3 · 中间件全家桶**（第 5-8 周） | 部署 Redis、Kafka、Nacos；**故意让 Redis 挂掉**看系统是否雪崩；用 JMeter 压测找瓶颈；`tail -f` + `grep` 定位线上 Bug | 模拟真实生产环境，获得排障经验 |
| **L4 · 微服务 + CI/CD**（第 9-12 周） | 拆分微服务用 Compose 全部跑起来；搭 Jenkins 或用 GitHub Actions；实现 **git push → 自动打包 → 构建镜像 → 重启服务** | 说出这段 CI/CD 搭建过程，面试官刮目相看 |
| **L5 · Agent 加分项**（第 11-14 周） | 部署 Ollama 跑开源模型 / 接入云 API；部署向量数据库 Milvus 或 Chroma；上线一个 Spring AI + RAG 应用 | 直接命中 JD "有 agent 开发经验优先" |
| **L6 · 个人品牌**（持续） | 用 Halo / Hexo / VuePress 搭个人博客；把踩坑记录写成文章 | 简历上的可访问链接 = 最强背书 |

### 🔒 服务器三条铁律

1. **绝不裸奔**：新买的服务器不配防火墙，几小时内就会被植入挖矿木马，CPU 拉满
2. **快照是后悔药**：折腾环境前先打快照，玩崩了一键回滚，别浪费时间重装系统
3. **配置建议**：学生优惠买 2核4G（2核2G 跑微服务吃力）。用 Docker Compose 限制内存，或先跑单体再升配

**今晚的行动**：SSH 连上服务器 → 装好 Docker → 跑起一个 Hello World 的 Nginx 容器。

```
【项目名】基于 Spring Cloud Alibaba 的分布式博客系统 | 2026.11 - 2027.01

       已部署于云服务器并通过域名访问。

【技术栈】Java 17 + Spring Boot 3 + Spring Cloud Alibaba + MySQL 8 + Redis 7 +
         Kafka 3 + MyBatis-Plus + Docker + Nginx

【核心工作】
• 使用 Redis 缓存热点文章与用户会话，配合 Caffeine 构建二级缓存，
  接口 P99 从 320ms 降至 45ms，QPS 提升约 6 倍
• 基于 Kafka 实现点赞、评论的异步解耦，削峰填谷，
  峰值写入场景下数据库压力降低 70%
• 使用 Nacos + OpenFeign + Gateway 完成微服务拆分，
  通过 Sentinel 配置熔断降级规则保障核心链路可用性
• 搭建 GitHub Actions 流水线，实现 push 后自动构建、Docker 打包、远程部署

【亮点】个人服务器部署，支持公网访问；Agent 模块基于 Spring AI 实现
       基于个人知识库的 RAG 问答
```

### 🎤 高频软技能问题预案

| 问题 | 回答思路 |
|---|---|
| **为什么从 C++ 转 Java？** | 强调兴趣 + 工程效率：C++ 让我理解内存与底层，Java 生态更适合快速构建大型后端系统；两者结合让我在排查 JVM / OS 层问题时更有优势 |
| **你才大二，凭什么胜任？** | 强调可塑性与投入度：从零到独立完成微服务项目只用了 X 个月，附博客/项目链接佐证 |
| **你的项目有什么不足？** | **诚实回答 + 改进方案**（例：目前是单机部署，下一步引入 K8s 做编排）。暴露真实思考比假装完美更受认可 |
| **遇到的最大困难？** | 用 STAR 讲一个真实踩坑故事，重点讲**排查过程**（如何看日志、如何定位、如何验证） |

## 八、心态建设

1. **大二投实习本来就是"越级挑战"**。和你竞争的有大三甚至研一的学生，被拒是常态，不是失败。
2. **这次的目标应该是"拿到面试经验"而不是"必须拿到 Offer"**。面 10 家挂 8 家，你也是赢家——你的真实目标是为明年**暑期实习**储备弹药。
3. **代码量是唯一不骗人的指标**。这 16 周结束时，你应该有 5000+ 行自己写的 Java 代码、2 个部署上线的项目、150+ 道八股、100+ 道算法。
4. **不要焦虑，要行动**。焦虑的反义词不是平静，是具体。今天就开始写第一行 Java。
